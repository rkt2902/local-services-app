# Detalhe do pedido — Cliente

**Ficheiro:** `lib/features/client/presentation/client_job_detail_screen.dart`

**Dependências novas:** nenhuma.

O ecrã cobre o resumo do pedido com status, timeline, serviço, data preferida, urgência, descrição, fotos e CTA para propostas. O `StatusTimeline` real é recebido já construído pelo wrapper para não inventar a assinatura desse widget partilhado.

```dart
import 'package:flutter/material.dart';
import 'package:riverpod/riverpod.dart' show AsyncValue;

import '../../../core/theme/app_colors.dart';
import '../../../core/theme/app_radius.dart';
import '../../../core/theme/app_spacing.dart';
import '../../../core/theme/app_status_color.dart';
import '../../../core/theme/app_status_presenters.dart';
import '../../../core/widgets/app_motion.dart';
import '../../../core/widgets/app_status_badge.dart';

class ClientJobDetailViewData {
  const ClientJobDetailViewData({
    required this.jobId,
    required this.jobReferenceLabel,
    required this.statusPresentation,
    required this.timelineSupportingLabel,
    required this.serviceLabel,
    required this.serviceMetaLabel,
    required this.serviceIcon,
    required this.preferredDateLabel,
    required this.urgencyLabel,
    required this.description,
    required this.proposalsActionLabel,
    required this.canOpenProposals,
    required this.canEditJob,
    required this.photos,
    this.newProposalsLabel,
    this.photosOverflowLabel,
  });

  final String jobId;

  /// Já formatado externamente.
  /// Ex.: "Pedido #1023".
  final String jobReferenceLabel;

  /// Presenter oficial de JobStatus.
  final AppStatusPresentation statusPresentation;

  /// Texto auxiliar da timeline.
  /// Ex.: informação sobre prazo de receção de propostas.
  final String timelineSupportingLabel;

  final String serviceLabel;

  /// Ex.: dimensão + localização, já formatadas.
  final String serviceMetaLabel;

  final IconData serviceIcon;

  /// Data/DateMode já convertido em texto.
  final String preferredDateLabel;

  /// Ex.: "Normal".
  /// É atributo textual, não estado.
  final String urgencyLabel;

  final String description;

  /// Ex.: label equivalente a "Ver 3 propostas".
  /// A contagem já vem resolvida externamente.
  final String proposalsActionLabel;

  /// Ex.: "3 novas".
  final String? newProposalsLabel;

  final bool canOpenProposals;
  final bool canEditJob;

  final List<ImageProvider> photos;

  /// Ex.: "+3", já calculado externamente.
  final String? photosOverflowLabel;
}

class ClientJobDetailScreen extends StatelessWidget {
  const ClientJobDetailScreen({
    super.key,
    required this.dataAsync,
    required this.statusTimeline,
    required this.onBack,
    required this.onOpenProposals,
    required this.onEditJob,
    this.onRetry,
  });

  final AsyncValue<ClientJobDetailViewData> dataAsync;

  /// StatusTimeline real do projeto, já configurado pela integração
  /// com os presenters oficiais de estado.
  final Widget statusTimeline;

  final VoidCallback onBack;
  final VoidCallback onOpenProposals;
  final VoidCallback onEditJob;

  final VoidCallback? onRetry;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      backgroundColor: AppColors.background,
      body: SafeArea(
        child: dataAsync.when(
          loading: () => _LoadingState(
            onBack: onBack,
          ),
          error: (_, __) => _ErrorState(
            onBack: onBack,
            onRetry: onRetry,
          ),
          data: (data) => _JobDetailContent(
            data: data,
            statusTimeline: statusTimeline,
            onBack: onBack,
            onOpenProposals: onOpenProposals,
            onEditJob: onEditJob,
          ),
        ),
      ),
    );
  }
}

class _JobDetailContent extends StatelessWidget {
  const _JobDetailContent({
    required this.data,
    required this.statusTimeline,
    required this.onBack,
    required this.onOpenProposals,
    required this.onEditJob,
  });

  final ClientJobDetailViewData data;
  final Widget statusTimeline;

  final VoidCallback onBack;
  final VoidCallback onOpenProposals;
  final VoidCallback onEditJob;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        _Header(
          title: data.jobReferenceLabel,
          presentation: data.statusPresentation,
          onBack: onBack,
        ),
        Expanded(
          child: ListView(
            key: PageStorageKey<String>(
              'client_job_detail_${data.jobId}',
            ),
            padding: const EdgeInsets.fromLTRB(
              AppSpacing.md,
              AppSpacing.sm,
              AppSpacing.md,
              AppSpacing.lg,
            ),
            children: [
              AppStaggeredEntrance(
                index: 0,
                child: _TimelineCard(
                  timeline: statusTimeline,
                  supportingLabel:
                      data.timelineSupportingLabel,
                ),
              ),
              const SizedBox(height: AppSpacing.md),

              AppStaggeredEntrance(
                index: 1,
                child: _ServiceSummary(
                  data: data,
                ),
              ),

              const SizedBox(height: AppSpacing.md),

              AppStaggeredEntrance(
                index: 2,
                child: _DetailsBlock(
                  preferredDateLabel:
                      data.preferredDateLabel,
                  urgencyLabel: data.urgencyLabel,
                ),
              ),

              const SizedBox(height: AppSpacing.md),

              AppStaggeredEntrance(
                index: 3,
                child: _DescriptionBlock(
                  description: data.description,
                  photos: data.photos,
                  photosOverflowLabel:
                      data.photosOverflowLabel,
                ),
              ),
            ],
          ),
        ),
        _BottomActions(
          proposalsActionLabel:
              data.proposalsActionLabel,
          newProposalsLabel:
              data.newProposalsLabel,
          canOpenProposals:
              data.canOpenProposals,
          canEditJob: data.canEditJob,
          onOpenProposals:
              onOpenProposals,
          onEditJob: onEditJob,
        ),
      ],
    );
  }
}

class _PhotoPreview extends StatelessWidget {
  const _PhotoPreview({
    required this.photos,
    required this.overflowLabel,
  });

  final List<ImageProvider> photos;
  final String? overflowLabel;

  @override
  Widget build(BuildContext context) {
    final visiblePhotos = photos.take(2).toList();

    return Wrap(
      spacing: AppSpacing.xs,
      runSpacing: AppSpacing.xs,
      children: [
        ...visiblePhotos.map(
          (photo) => ClipRRect(
            borderRadius: BorderRadius.circular(
              AppRadius.input,
            ),
            child: Image(
              image: photo,
              width: 56,
              height: 56,
              fit: BoxFit.cover,
            ),
          ),
        ),
        if (overflowLabel != null)
          _PhotoOverflow(
            label: overflowLabel!,
          ),
      ],
    );
  }
}

                MainAxisAlignment.center,

                Icons.description_outlined,

                  label,

                    color: foreground,
                    fontWeight: FontWeight.w700,

                  padding: const EdgeInsets.symmetric(
                    horizontal: AppSpacing.xs,

                        : AppColors.background,
```

## Notas de integração

- `statusPresentation` vem obrigatoriamente do presenter oficial de `JobStatus`. O ecrã nunca decide se o pedido está `waiting`, `info`, `success`, etc.
- O **`StatusTimeline` real é injetado em `statusTimeline`**. Isto evita recriar o componente ou inventar a sua assinatura. O wrapper configura os nós `Publicado → Propostas → Escolher → Confirmado` com o estado real.
- A regra de cores da timeline continua a ser a definitiva: o passo atual usa o token real do estado, passos futuros usam `neutral`.
- `timelineSupportingLabel` também chega pronto; o ecrã não calcula deadlines nem formata data/hora.
- O CTA recebe `proposalsActionLabel` e `newProposalsLabel` já preparados. Assim não é usado `proposals.length` para fabricar `"Ver 3 propostas"` ou `"3 novas"`.
- O estado `open com propostas` deve continuar a chegar do presenter como **“N proposta(s)” / waiting**. O pequeno `"3 novas"` do CTA é apenas contagem auxiliar, não outro estado.
- `Data preferida` e `Urgência: Normal` são mostradas como atributos. Não recebem badge. Se existir a flag real **Urgente**, a integração deve continuar a usar o componente/presenter de urgência com `AppStatusColor.cancelled` onde o produto definir essa apresentação.
- `serviceLabel`, `serviceMetaLabel`, data, localização, descrição e ícone vêm todos dos dados reais.
- As fotografias são `ImageProvider`; nenhuma URL ou foto é inventada. `photosOverflowLabel` permite mostrar `+N` sem o ecrã calcular a contagem.
- `canEditJob` e `canOpenProposals` vêm das regras de domínio externas. O ecrã não decide até que estado um pedido pode ser editado.
- `PageStorageKey` preserva o scroll quando o utilizador entra nas propostas e volta.
