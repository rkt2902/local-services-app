# 1a. Criar pedido — Passo 4: Rever e publicar

**Ficheiro:** `lib/features/client/presentation/create_job_review_screen.dart`

**Dependências novas:** nenhuma.

Este passo entra **depois de “Descrição e fotos” e antes da publicação real**. Recebe todo o draft já resolvido, não conhece providers/Supabase e mantém os três cartões editáveis separados para voltar exatamente ao passo correspondente.

class CreateJobPublishResult {
  const CreateJobPublishResult._({
    required this.success,
    this.errorMessage,
  });

  const CreateJobPublishResult.success()
      : this._(
          success: true,
        );

  const CreateJobPublishResult.failure({
    required String errorMessage,
  }) : this._(
          success: false,
          errorMessage: errorMessage,
        );

  final bool success;
  final String? errorMessage;
}

class CreateJobReviewScreen extends StatefulWidget {
  const CreateJobReviewScreen({
    super.key,
    required this.data,
    required this.stepProgress,
    required this.onBack,
    required this.onEditService,
    required this.onEditScheduling,
    required this.onEditDescriptionAndPhotos,
    required this.onPublish,
    required this.onPublished,
  });

  final CreateJobReviewViewData data;

  /// Deve receber o AppStepProgress real do projeto,
  /// configurado pelo integrador para 4 passos / passo atual 4.
  ///
  /// É injetado porque a assinatura concreta do AppStepProgress
  /// não foi fornecida e não devemos inventá-la.
  final Widget stepProgress;

  final VoidCallback onBack;

  final VoidCallback onEditService;
  final VoidCallback onEditScheduling;
  final VoidCallback onEditDescriptionAndPhotos;

  /// Só devolve success depois de o backend confirmar
  /// efetivamente a publicação.
  final Future<CreateJobPublishResult> Function() onPublish;

  /// Callback exterior para a navegação pós-publicação.
  final VoidCallback onPublished;

  @override
  State<CreateJobReviewScreen> createState() =>
      _CreateJobReviewScreenState();
}

class _CreateJobReviewScreenState
    extends State<CreateJobReviewScreen> {
  bool _publishing = false;
  bool _successVisible = false;

  bool get _interactionEnabled => !_publishing;

  Future<void> _publish() async {
    if (_publishing) {
      return;
    }

    FocusScope.of(context).unfocus();

    setState(() {
      _publishing = true;
      _successVisible = false;
    });

    CreateJobPublishResult result;

    try {
      result = await widget.onPublish();
    } catch (_) {
      if (!mounted) {
        return;
      }

      setState(() {
        _publishing = false;
      });

      return;
    }

    if (!mounted) {
      return;
    }

    if (!result.success) {
      setState(() {
        _publishing = false;
      });

      final message = result.errorMessage;

      if (message != null && message.isNotEmpty) {
        ScaffoldMessenger.of(context)
          ..hideCurrentSnackBar()
          ..showSnackBar(
            SnackBar(
              content: Text(message),
            ),
          );
      }

      return;
    }

    setState(() {
      _publishing = false;
      _successVisible = true;
    });

    widget.onPublished();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      backgroundColor: AppColors.background,
      body: SafeArea(
        child: Stack(
          children: [
            Column(
              children: [
                _Header(
                  onBack: _interactionEnabled
                      ? widget.onBack
                      : null,
                ),
                Padding(
                  padding: const EdgeInsets.fromLTRB(
                    AppSpacing.md,
                    AppSpacing.xs,
                    AppSpacing.md,
                    AppSpacing.md,
                  ),
                  child: IgnorePointer(
                    ignoring: !_interactionEnabled,
                    child: widget.stepProgress,
                  ),
                ),
                Expanded(
                  child: IgnorePointer(
                    ignoring: !_interactionEnabled,
                    child: ListView(
                      padding: const EdgeInsets.fromLTRB(
                        AppSpacing.md,
                        0,
                        AppSpacing.md,
                        AppSpacing.lg,
                      ),
                      children: [
                        AppStaggeredEntrance(
                          index: 0,
                          child: _Intro(),
                        ),
                        const SizedBox(
                          height: AppSpacing.sm,
                        ),
                        AppStaggeredEntrance(
                          index: 1,
                          child: _ServiceCard(
                            data: widget.data.service,
                            onEdit:
                                widget.onEditService,
                          ),
                        ),
                        const SizedBox(
                          height: AppSpacing.sm,
                        ),
                        AppStaggeredEntrance(
                          index: 2,
                          child: _SchedulingCard(
                            data:
                                widget.data.scheduling,
                            onEdit:
                                widget.onEditScheduling,
                          ),
                        ),
                        const SizedBox(
                          height: AppSpacing.sm,
                        ),
                        AppStaggeredEntrance(
                          index: 3,
                          child:
                              _DescriptionPhotosCard(
                            data: widget.data
                                .descriptionAndPhotos,
                            onEdit: widget
                                .onEditDescriptionAndPhotos,
                          ),
                        ),
                      ],
                    ),
                  ),
                ),
                _BottomAction(
                  publishing: _publishing,
                  onPublish: _publish,
                ),
              ],
            ),
            AppSuccessFeedback(
              visible: _successVisible,
              message: 'Pedido publicado com sucesso.',
            ),
          ],
        ),
      ),
    );
  }
}

class _PhotosPreview extends StatelessWidget {
  const _PhotosPreview({
    required this.photos,
    required this.overflowLabel,
  });

  final List<ImageProvider> photos;
  final String? overflowLabel;

  @override
  Widget build(BuildContext context) {
    final visiblePhotos = photos.take(2).toList();

    return Wrap(
      spacing: AppSpacing.xs,
      runSpacing: AppSpacing.xs,
      children: [
        ...visiblePhotos.map(
          (photo) => ClipRRect(
            borderRadius: BorderRadius.circular(
              AppRadius.input,
            ),
            child: Image(
              image: photo,
              width: 64,
              height: 64,
              fit: BoxFit.cover,
            ),
          ),
        ),
        if (overflowLabel != null)
          _PhotoOverflow(
            label: overflowLabel!,
          ),
      ],
    );
  }
}

## Notas de integração

- Este é o novo **passo 4**. O wrapper deve passar o `AppStepProgress` real configurado para **4 passos, passo atual 4**. Não inventei a assinatura desse widget partilhado porque ainda não foi fornecida.
- Os três callbacks `onEditService`, `onEditScheduling` e `onEditDescriptionAndPhotos` devem voltar aos passos 1, 2 e 3 **mantendo o mesmo draft**. A transição `shared axis X` invertida indicada no mock fica na camada de navegação.
- `serviceLabel`, ícone, data, dimensão, morada, descrição e imagens vêm todos do draft real. Não há serviços, datas, moradas ou tamanhos de exemplo hardcoded.
- `SizeEstimate` continua como **texto simples**, não badge.
- As fotos não são obrigatórias. Quando a lista está vazia, aparece **“Sem fotos adicionadas”**, conforme o mock.
- `photosOverflowLabel` vem externamente, permitindo ao integrador apresentar `+N` sem este ecrã assumir se recebeu a lista completa de fotografias.
- Enquanto `onPublish()` está em curso, **voltar, editar e publicar ficam bloqueados** e o CTA passa para **“A publicar...”**.
- Em erro de publicação, o callback pode devolver `CreateJobPublishResult.failure(errorMessage: ...)`; o ecrã mostra `SnackBar` e **não altera qualquer dado do draft**.
- `AppSuccessFeedback` só é ativado quando `onPublish()` devolve `success`, portanto nunca é otimista.
- `onPublished` é o único ponto usado para avançar/navegar depois da publicação confirmada. O ecrã não conhece a rota seguinte.
- Os três cartões entram com `AppStaggeredEntrance`. Em `disableAnimations`, o comportamento reduzido fica delegado ao motion system existente.
